    Course Handbook¶

    Course Objectives¶

    The course introduces students to the fundamentals of database management systems and their architecture. Emphasis is given to the popular relational database system, including data models and data manipulation. Students learn the importance of database structure and its design — both the conceptual approach using the Entity Relationship model and the formal approach using normalisation. The importance of file indexing and the controlled execution of transactions is taught. The course gives students hands-on practice of structured query language in a relational database management system and a glimpse of basic database administration commands.

    Learning Outcomes¶

    On successful completion, students will be able to:

    • Use database management system software to create and manipulate a database.
    • Create conceptual data models using entity relationship diagrams for modelling real-life situations and designing the database schema.
    • Use the concept of functional dependencies to remove redundancy and update anomalies.
    • Apply normalisation theory to obtain a normalised database schema.
    • Write queries using relational algebra, a procedural language.

    The Running Example¶

    One schema is used throughout every unit, so that each new idea is applied to data students already know.

       +-------------------+                +-------------------------+
   |      STUDENT      |                |         COURSE          |
   +-------------------+                +-------------------------+
   | PK Rollno         |                | PK SID                  |
   |    Name           |                |    Cname       (UNIQUE) |
   |    Dateofbirth    |                |    TotalSeats  (> 0)    |
   +---------+---------+                |    Duration             |
             |                          |    Coursetype  (F / P)  |
             |                          |    TeacherInCharge      |
             |                          +------------+------------+
             |    +---------------------+            |
             +----+      ADMISSION      +------------+
             |    | PK,FK Rollno / SID  |
             |    |    Dateofadmission  |
             |    +---------------------+
             |
             |    +---------------------+        +----------------+
             +----+     ENROLLMENT      +--------+    SOCIETY     |
                  | PK,FK Rollno / SocID|        | PK SocID       |
                  |    Dateofenrollment |        |    Socname     |
                  +---------------------+        |    Mentor      |
                                                 |    TotalSeats  |
                                                 +----------------+

    How it threads through the course: Unit 2 derives this from requirements as an ER diagram; Unit 3 states its keys and integrity constraints and queries it in relational algebra; Unit 4 implements and queries it in SQL; Unit 5 maps the ER diagram to exactly these tables and proves them normalised; Unit 6 indexes them and runs transactions over them.

    A note on the schema

    The syllabus PDF describes this schema in a diagram that did not survive text extraction. The version used here follows the syllabus's stated facts — "Rollno (ADMISSION) and SID (ADMISSION) are foreign keys", "course type may have two values viz. Fulltime and Parttime", "a student may enroll in any number of courses" — together with the attributes implied by the twenty-five prescribed queries. If your class is issued a schema differing in column names, every query transfers unchanged apart from those names.

    The mistakes that cost the most marks¶

    1. Forgetting DISTINCT after a join that can duplicate rows.
    2. Using COUNT(*) after a LEFT JOIN when counting matches — it reports 1 instead of 0.
    3. Putting an aggregate condition in WHERE instead of HAVING.
    4. Omitting parentheses when mixing AND with OR.
    5. Not finding all candidate keys before judging the normal form — every 2NF and 3NF test depends on which attributes are prime.
    6. Confusing partial with transitive dependency, and so the wrong normal form.
    7. Claiming an entity is weak because it "depends on" another — the test is identification, not dependence.
    8. Mixing up cardinality and participation, or forgetting that each side is decided separately.
    9. Using ∧ where ∩ is needed in relational algebra, when the two facts are in different tuples.
    10. Writing = NULL instead of IS NULL.
    11. Reversing the (min, max) labels relative to Chen notation.
    12. Forgetting the leading join in the "only" query (Practical 12), so students with no admissions qualify vacuously.

    A revision route¶

    1. Work through the Quiz page unit by unit; it will tell you which units are weak.
    2. Re-read the summary box at the end of each weak lesson, then its solved questions.
    3. Do every exercise in the SQL Playground until all 50 pass.
    4. Use the Normalisation Trainer on the past-paper relations; check your hand-worked candidate keys and normal form against its output after attempting them yourself.
    5. Draw the COMPANY and college ER diagrams from memory; they exercise every notational feature.
    6. Rehearse the viva questions at the end of the Laboratory Manual.
